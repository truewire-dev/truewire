# Rust rules

These rules cover the Rust crate: the generated modules under `src/<package>/`, the
hand-written `core` module, and `tests/`. Each rule names the tool that enforces it, or says
(review) when a reviewer checks it by reading the code.

## Tools

- `truewire lint rust` runs `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings`
  where `Cargo.toml` is. Every warning is an error, in `tests/` too.
- Don't add a `rustfmt.toml`. Generated files are printed to rustfmt's defaults (100 columns)
  and no formatter runs over them, so a changed width fails `cargo fmt --check`. (rustfmt)
- Keep `edition = "2021"` in `Cargo.toml` (`cargo new` writes 2024). Generated files follow
  rustfmt's 2021 style; under 2024 `cargo fmt --check` re-sorts every generated `use`
  list. (rustfmt)
- An `#[allow(..)]` goes on the one item that needs it, names one lint, and has a comment
  saying why. A call to a `#[deprecated]` generated method needs
  `#[allow(deprecated)]` on the caller. No crate-level `#![allow]` in hand-written code.
  (review)

## Generated and hand-written code

- Never edit a file that starts `//! Generated by truewire — do not edit by hand.` Change the
  spec or `truewire.toml` and regenerate. (`truewire generate rust --check`)
- A clippy or compile error in a generated file is a generator bug. Report
  it with the spec input that causes it. Don't patch the file. (review)
- `core/` is the one module the generator does not write. A method you add to a generated
  type (the root's `new`/`try_new`, a `surface: handwritten` endpoint) is an inherent `impl`
  in a file under `core/`. (review)
- In a gRPC project `protos/` is owned by `truewire protos rust`; never edit it.
  (`truewire protos rust --check`)
- If one wire enum shows up as two Rust types (`RequestZoneType`, `ZoneType2`), the spec
  declares it inline twice. Fix the spec with one shared schema `$ref`ed from every use.
  Don't add conversions in the core. (review)

## Naming and types

- `snake_case` functions, fields and modules; `UpperCamelCase` types and variants;
  `SCREAMING_SNAKE_CASE` constants. (rustc lints, denied by `-D warnings`)
- A field whose wire name is not snake_case gets a snake_case name and
  `#[serde(rename = "wireName")]`. A keyword gets a trailing `_` (`type_`). (review)
- No `Default` on a type without a meaningful zero, such as a required enum or a timestamp.
  A `#[default]` variant silently sends that value. (review)
- Convert a caller-supplied integer with `try_from`, never `as`. `-1 as usize` is
  `usize::MAX`, and an unchecked size of 0 panicked as a divisor. (review)

## Errors

- Return `truewire_core::Result`. Build each failure with an `Error` constructor:
  `network` when the server was not reached, `validation` when a reply has the wrong shape,
  `logic` when the core refuses before sending, `auth` also for credentials it cannot use
  (an undecodable key). For an error the API returned, use `auth`,
  `rate_limited`, `bad_request` or `api` with `.with_status(..)` and `.with_body(..)`. No
  crate-specific error type. (review)
- No `.unwrap()` in `src/`. Use `.expect("..")` only where the code rules out failure (a
  poisoned lock, a value it just checked), with a message saying why. (review)
- A constructor that can fail on its options has a `try_new` that returns `Result`. `new`
  panics only through `try_new(..).expect(..)` and documents it under `# Panics`. (review)

## Async and cancellation

- Don't hold a `std::sync::Mutex` guard across `.await`. Use `tokio::sync::Mutex` there.
  (clippy `await_holding_lock`)
- A caller can drop any future (`tokio::time::timeout`, `select!`). If an async fn registers
  state before an `.await` (a pending reply, a reserved rate slot, a subscription entry), a
  drop guard removes it, not only the `Err` path. (review)

## The core and tests

- Credentials arrive in `CoreOptions`. The core never reads the environment. (review)
- Sign inside the `HttpClient::request_prepared` callback, so each paced or retried attempt
  gets a fresh nonce or timestamp. Never sign before the call. (review)
- Build the default `HttpClient` with `.with_rate(<Root>::RATE).with_retry(<Root>::RETRY)`.
  A client passed in through `CoreOptions::http` is used as is; its doc says so.
  (review)
- A type that holds a secret (a token, a key, or a proxy URL, which can carry
  `user:password`), `CoreOptions` included, implements `Debug` by hand and leaves the
  secret out. An
  accessor that returns a URL strips its username and password. (review)
- `tests/` run against `truewire mock`, started as a child process on free ports, never the
  live API (see `tests/common/mod.rs` in the toolchain's examples). `truewire-testing`
  (`Mock::start`, `replay`) is unpublished, so only crates inside the toolchain repository
  can use it. `truewire test rust` runs the tests. (review)

## Dependencies and compatibility

- Use `serde_json`, `chrono` and `bigdecimal` through `truewire_core`'s re-exports, as
  generated code does, not as direct dependencies. (review)
- If regenerated code uses a `truewire-core` item newer than the `Cargo.toml` floor, raise
  the floor to the first release that has it and commit the new `Cargo.lock`.
  (review)
- Keep a TLS feature on `truewire-core` (`rustls-tls`, the default, or `native-tls`).
  Without one, every `https://` call fails; truewire-core 0.1 sent such a call in
  cleartext through a proxy. (review)
- Moving a public path, or adding a field to a struct whose fields are all `pub` (every
  generated record), breaks callers even when Python sees no change. Release it as a
  breaking version, with a CHANGELOG written against the published crate, not the PR
  base. (review)
