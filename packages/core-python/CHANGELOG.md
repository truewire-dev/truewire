# Changelog

## 0.3.0 (2026-09-30)

- `EpochConverter.parse` takes a `float` or a fractional numeral string and keeps the
  sub-second part, using exact `Fraction` arithmetic; below a microsecond it rounds to the
  nearest one. 0.2.1 truncated through `int()` (`1688669448.4712` parsed as `18:50:48`)
  and raised on `"1.5"`. Code generated by truewire 0.11 relies on this for `type: number`
  timestamps.

- WebSocket subscriptions retain their original connection across reads and unsubscribe.
  A dropped stream raises `NetworkError` instead of reconnecting without subscribing.
  Work inside `Socket.wait` resolves `ctx` only against that connection. Cancelling a
  connect waiter no longer cancels the shared connection attempt; cancelling the owner
  releases other waiters with `NetworkError`. Refused and timed-out connections also
  raise `NetworkError`, with the original transport error as their cause.
  `unsubscribe` after the connection dropped sends nothing, returns `None` and frees the
  channel for a new `subscribe`; if it fails while the connection is still up, the
  subscription stays and `unsubscribe` can be retried.
  A stream read delivers notifications queued before a drop, then raises; an unsubscribed
  stream ends cleanly and never takes a newer subscription's queue. A connection whose
  listener died (a frame `on_msg` could not read) is replaced on the next call, and a bound
  read raises the listener's own exception. A connect that completes after its owner left
  `async with` closes itself and raises `ClosedByOwner` (a `NetworkError`); `close()` closes
  each connection once and aborts it if cancelled mid-handshake.

- `TimestampSecondsFloat`, `TimestampMillisFloat`, `TimestampMicrosFloat` and
  `TimestampNanosFloat` (converters `timestamp_seconds_float`, ...; class
  `EpochNumberConverter`): the aliases for a `type: number` epoch. They parse like
  `TimestampSeconds` and friends and dump the fraction back, as an `int` when the count is
  whole and a `float` otherwise, so `1688669448.4712` is sent as `1688669448.4712`, not
  `1688669448`. The integer aliases still dump a whole count.

- `Rpc.rpc_request` and `StreamsRpc.rpc_request` remove their reply future however the
  call ends. A call cancelled by the caller (an `asyncio.wait_for` timeout), a send that
  raised or a dropped connection used to leave it in `replies` for the life of the
  connection; `on_msg` now drops a reply whose id has no waiter instead of raising `KeyError`.

- `HttpClient(rate=, retry=)`, the runtime side of `[policy]` (packages clause P19). `rate`
  spaces request starts `1 / rate` seconds apart across every caller of the client (ten
  requests at `rate=5` span 1.8 s); a rate that is not positive and finite is a
  `ValueError`. `retry=True` sends a request again, up to `RETRY_ATTEMPTS` (3) in all,
  after an `httpx.ConnectError`/`ConnectTimeout` (nothing sent) or a 429/503 reply, waiting
  its `Retry-After` (seconds or an HTTP date; `retry_after(response)`) or else 0.5 s
  doubling. A `Retry-After` over `RETRY_AFTER_CAP` (30 s) returns the reply. No other
  status and no failure after sending is retried, nor a streamed or file body. Every
  attempt is paced and recorded. Both default off, which changes nothing. A caller
  cancelled while waiting for its pacing slot frees the slot. A connection error when
  redirects are enabled, or a reply reached through a redirect, is not retried, so a
  request that a redirect already acted on is never sent again.
- `proxy=` on `HttpClient` and on every WebSocket class (`Socket` and its subclasses), a
  HTTP(S) proxy URL such as `http://host:3128` that the connection goes through: httpx
  forwards plain `http://` requests and tunnels `https://` ones, and websockets sends
  `CONNECT`. Left `None` (or `''`), each library reads the environment as before:
  `HTTPS_PROXY`/`HTTP_PROXY`/`NO_PROXY` on both, `ALL_PROXY` on HTTP only,
  `WS_PROXY`/`WSS_PROXY` on WebSocket only. With no proxy variable set, both fall back
  to the system proxy settings on macOS and Windows; only websockets also honours the
  system bypass list, so a host it exempts goes direct over WebSocket but through the
  proxy over HTTP. An explicit one ignores the environment and the system settings,
  `NO_PROXY` included. A `socks5://` URL needs `httpx[socks]` and
  `python-socks`, which this package does not install. Packages clause P18: a sandbox or a library caller
  cannot always set the process environment. `HttpClient.limits` now defaults to `None`,
  which keeps no connection alive behind a proxy, explicit or from the environment.
  Requires `websockets>=15` and `httpx>=0.26`, the first releases with a `proxy` argument.

## 0.2.1 (2026-09-08)

- `truewire_core.times`: every converter's `parse` returns an already-parsed value
  unchanged -- a `date` to `DateConverter`, a `datetime` to `IsoConverter` and
  `EpochConverter` -- so a request `TypedDict` holding the real `date`/`datetime` its
  generated signature asks for validates through `BeforeValidator(parse)` instead of
  failing in `strptime`/`endswith`/`int()`. `DateConverter` takes a `datetime` only at
  midnight (its `date()`, nothing lost) and raises `ValueError` for any other time of day
  rather than truncating silently, the rule pydantic applies to a `date` field. `dump` is
  unchanged.

## 0.2.0 (2026-09-08)

- `truewire_core.types`: the timestamp and date aliases generated code imports by name
  (`TimestampSeconds`, `TimestampMillis`, `TimestampMicros`, `TimestampNanos`,
  `TimestampIso`, `DateIso`) and the converter instance behind each. They were written into
  every project's `core/types.py` by `truewire init`, identical everywhere; generated code
  now imports them from here, and a project's `core/types.py` is a re-export kept for
  callers that import it.
- `truewire_core.contract`: `Protocol`s for the contract between a hand-written core and
  generated code: `HttpEndpoint` (`request` with `method`), `CommandEndpoint` (`request`
  without it), `StreamEndpoint` (`subscribe`), `ClientRoot` (`new`, `__aenter__`,
  `__aexit__`) and `Composite` (`new(client, *, ...)`). The generator no longer imports a
  project's package to learn this shape (ADR 0011).

## 0.1.1 (2026-09-07)

- `truewire_core.http.recording()`: a context manager that records every request and
  response an `HttpClient` makes inside the block, at the wire level. `truewire capture`
  is built on it.

## 0.1.0 (2026-09-07)

First release. The runtime behind clients generated by `truewire`: HTTP and WebSocket
transports, runtime validation, pagination walkers, timestamp converters and typed error
types. Forked from `typed-core` and renamed; `EpochConverter` now uses integer arithmetic
so nanosecond timestamps round-trip exactly.
