# Changelog

## 0.11.0 (2026-10-01)

- **`call typescript` dumps a result through its codec.** The driver read the response
  codec before the call recorded it, so an HTTP result went out as the client's typed
  value: a `Date` printed as `toISOString` (`...02.000Z`), not the wire's `...02Z`. With
  `@truewire/core`'s group-of-three fractions, the github and kraken examples print every
  timestamp as recorded. With validation off for the call (the call's `validate`, else the
  core's, as with `--new validate=false`) the core returns raw JSON, which is printed as it
  is rather than dumped through the codec.

- **Declared comma-separated query arrays replay in the mock.** `match.query_arrays`
  lets the mock match a comma-separated query value against the recorded list, without
  changing how undeclared query parameters match (ADR 0019).
- **Pagination standards recognise quoted types and inherited methods.** Python
  `PaginatedResponse` annotations written as strings and page methods inherited from a
  parent class no longer produce false missing-pagination findings.
- **Python starter cores export number-epoch aliases.** `init` includes the
  `TimestampSecondsFloat`, `TimestampMillisFloat`, `TimestampMicrosFloat` and
  `TimestampNanosFloat` aliases needed by fractional epoch fields.
- **New Python projects stop printing credentials in client representations.** `init`
  excludes client credential fields from `repr`, including representations of nested cores.
- **Rust chains wrap at the configured width.** The generator accounts for the space
  taken by the final call and uses fully qualified `::core::option::Option` for root rate
  policy values, so a generated type named `Option` cannot shadow the standard type.
- **Rust chains that fit stay on one line below long bindings.** An overflowing `let`
  prefix no longer makes a short right-hand-side chain wrap unnecessarily.
- **Rust bindings reserve space for a trailing `?`.** Generated fallible expressions
  near the line limit remain within the configured width after error propagation.
- **Rust example clients redact credentials in `Debug` output.** Inspecting the GitHub
  or Kraken example core no longer prints its authentication fields.
- **Vendored rules cover all four languages.** `init` and `agents update` ship Python,
  TypeScript, Rust and Go guidance, including the current Python pagination contract.
- **Matching agent files behind shared links stay untouched.** `agents update` accepts
  an unchanged shared copy whose stamp names an older toolchain version, while still
  refusing edits or removals outside the project.

- **Runtimes.** Code generated by 0.11 needs `truewire-core` 0.3.0 (Python),
  `@truewire/core` 0.2.0 and the Rust `truewire-core` 0.2.0. The toolchain and `init`
  require `truewire-core>=0.3.0,<0.4`; a Rust crate names `truewire-core = "0.2"`. The Rust
  0.2 is a breaking release (`DecimalString`, `IntegerString` and the new
  `CallOptions.transport` field),
  so a crate generated by 0.10 stays on 0.1.1. TypeScript's `t.integerString` now returns
  `bigint` instead of `number`; update arithmetic and literals accordingly.
- **`generate` refuses an empty endpoint tree.** A project with no `endpoint.json`
  files raises `CodegenError` before generating a client. A missing spec is an error,
  rather than a successful generation with no endpoints.
- **S1 endpoint inventory.** `spec/inventory.json`, described by
  `inventory.schema.json`, lists the upstream operations independently of the spec.
  Entries can name an endpoint, give an exclusion reason, or remain unspecified with
  neither. `score` shows resolved/total and lists unspecified operations with
  `--verbose`; a missing, unapproved or incomplete inventory fails coverage. `check`
  rejects duplicate method-and-path pairs, comparing methods case-insensitively and
  naming both entry indexes. Approval confirms the upstream list, not spec completion.
- **Python written by `init` passes `truewire lint`.** The generated starter and core
  templates satisfy the package's formatter, linter and type checker without
  manual cleanup, so S7 can pass on the new project's Python package.
- **A number with a timestamp `format` generates a timestamp type (breaking for
  regenerated Python, TypeScript and Rust code).** Every `type: number` field with
  `format: epoch-seconds` (or another epoch format) changes from Python `float`,
  TypeScript `number` or Rust `f64` in 0.10 to Python `TimestampSecondsFloat` (a
  `datetime`), TypeScript `TimestampSeconds` (a `Date`, codec `t.epochSecondsFloat`),
  or Rust `TimestampSecondsFloat`. The millis, micros and nanos formats use their
  corresponding types and codecs. Fractions survive parsing and sending within each
  language's timestamp precision: microseconds in Python, nanoseconds in TypeScript
  and Rust. Integer schemas keep their integer-dumping types and codecs. Regenerating
  changes these fields in every client, including kraken's `time`, moralis's
  `blockTime` and dydx's `epoch`. Code that does arithmetic on them, such as
  `time.time() - trade['time']`, must use the language's timestamp operations instead.

- **A `seek` cursor is read in the row field's own timestamp format**. A row
  `timestamp` in `epoch-seconds` under an `epoch-millis` bound (lighter's fundings) was
  parsed as milliseconds by an unvalidated Python or TypeScript walk, and by every Rust
  walk, so page 2 went out with `end_timestamp` a thousand times too small. The plan
  carries the cursor field's type (`pagination.cursorType`); Python's `key_of`, the
  TypeScript `keys` converter and Rust's `Seek::cursor::<T>()` parse the row value in its
  own format, and the request encodes the next bound in the bound's. Go already did. A
  walker whose row and bound share a format is unchanged. `truewire check` now accepts any
  instant format (`epoch-*`, `date-time`) under an instant bound, and refuses a cursor with
  no timestamp format under a timestamp bound, or a `date` under an instant one, naming
  both fields. A regenerated Rust walker that needs it calls `Seek::cursor`, which is new
  in `truewire-core` 0.2.0.

- The HMAC init template and Kraken example sign after pacing on every retry, using
  fresh timestamps/nonces. Python uses HTTPX auth hooks; TypeScript and Rust cores use
  the runtime preparation hooks.

- **`router.json` declares `class`**: a group's generated class name, in place of the
  PascalCase of its directory, in every backend (Python and TypeScript class, Rust struct,
  Go type). The parent's accessor keeps the directory's name: `"class": "ChainRpc"` on
  `chain/rpc/` gives `client.chain.rpc` of type `ChainRpc`. The words are the author's;
  the letter case follows each language, so Go, which re-cases initialisms in every name,
  renders `ChainRPC`. Rule 18 judges the declared name. `truewire plan --json` carries it
  as the child's `class`.
- **An invalid `router.json` is a finding, not a traceback**: `truewire check` reports it
  under rule 14, naming the file (as it does a `class` on the root `router.json`), and
  `truewire generate` refuses it before writing anything.
- **`truewire docs check` validates `docs/docs.yml`** (`docs/shape/workspace.md`, W10; S9).
  An unknown key, a nav page missing under `docs/`, a quickstart missing a language
  `truewire.toml` declares, or a block for one it does not, each fails naming the key. A
  project without `docs/docs.yml` is unaffected; the layout check reports it. `init` now
  writes one stub quickstart block per declared language, so a fresh project passes.
- **JSON Schemas for `docs.yml` and `truewire.toml`** (`docs/shape/toolchain.md`, T7). The
  pydantic models live in `truewire.schemas` (`docs/`, `config/`), and `python -m
  truewire.schemas` writes `docs.yml.json` and `truewire.toml.json` into
  `truewire/schemas/published/`, committed and shipped in the package; a test fails when
  they drift from the models. `truewire.toml.json` has no `null` branch, since TOML has no
  null, so an editor names the key a typo is in. They are not served at
  `truewire.dev/schemas/` yet.
- `truewire.toml` refuses an unknown `[project]` or `[spec]` key, as every other table
  already did, and a `[spec].dir` that is not a non-empty string.
- **`[policy].rate` and `[policy].retry` reach the client** (`docs/shape/workspace.md` W15,
  `docs/shape/packages.md` P19). The generated root states them: `RATE`/`RETRY` class
  attributes in Python (only when `[policy]` sets one, the core's base declaring `None` and
  `False`), `static readonly RATE`/`RETRY` in TypeScript and associated consts in Rust
  (always). Every `truewire init` template's `ClientBase.new(...)` builds
  `HttpClient(proxy=proxy, rate=cls.RATE, retry=cls.RETRY)`, and the `examples/github` and
  `examples/kraken` cores do the same in all three languages. A project initialised before
  this has to pass them on in its own core, since `generate` never rewrites a core.
  `generate go` prints a `skipped` line for each of the two it cannot render. The runtimes'
  pacing and retry are in `truewire-core` 0.3.0, `@truewire/core` 0.2.0 and the Rust
  `truewire-core` 0.2.0.
- **`[policy].refuse` is generated** (`docs/shape/workspace.md`, W15). An endpoint it names
  keeps its generated method in Python, TypeScript and Rust. The method fails with
  `RefusedByPolicy` before any request is made: raised in Python, a rejected promise in
  TypeScript, an `Err` in Rust. The error is generated into the package (`policy.py`,
  `policy.ts`, `policy.rs`), so no runtime release is needed. It is a `LogicError` of each
  runtime; in Rust it is the `source` of an `Error::Logic`, found with
  `RefusedByPolicy::of`. Python wraps every public method of the endpoint class
  (`@refused`); TypeScript and Rust open every body that reaches the core with `refuse(...)`.
  A project with nothing refused gets no `policy` module and no changed file. `generate`
  fails (Go included) when a refusal names no generated endpoint, or an endpoint whose
  method is written by hand: `surface: handwritten`, a `[python.extras]` or
  `[typescript.extras]` entry that `replaces` it, or a `[python].backend` `skip_endpoint`.
  `generate python` also fails when a backend override renders a refused endpoint without
  `@refused`. `generate go` renders no refusal yet and prints one `skipped` line per
  refused endpoint. `examples/kraken` refuses `spot.funding.withdraw`. The plan carries it as
  `EndpointPlan.refused`.
- **`seek` declares `exclusive` (ADR 0013)**: request parameters the venue refuses beside the
  moving bound, as aster's `userTrades` refuses `startTime`/`endTime` beside `fromId`. Every
  backend's walker sends them on the first request only, refuses the moving bound beside
  any of them but `far` (and, with `first`, neither), and keeps `far` itself: it drops
  every row whose `time` is past the caller's own `endTime`, and ends the walk on the page
  that held one. `fromId` + `endTime` resumes a capped walk without sending `endTime`.
  `truewire check` validates the named parameters, and that `far.parameter` has an order
  and agrees with `far.field` on the timestamp format; `truewire plan --json` carries the
  declaration in the `seek` decision.
- **`truewire init` over an existing project adds the `#:schema` line** (W13). A
  `truewire.toml` that names no schema gets `#:schema https://truewire.dev/schemas/truewire.toml.json`
  as its first line, in the file's own line ending; every other byte stays as it was, and
  the `Filled in` line says so. So a project whose `truewire.toml` predates W13 passes the
  layout check after `truewire init .`, with no hand edit. A file with a `#:schema` line
  anywhere, whatever its URL, is left alone: `truewire standards` reports one that is wrong
  or not on line 1. So is a symlinked `truewire.toml`. A second run prints `Nothing changed`.
- **`truewire lint [language]`** (`docs/shape/toolchain.md` T3, T4). It runs each declared package's own formatter, linter and type checker in the package's directory, the one `truewire test` runs in (the nearest `pyproject.toml`, `package.json`, `Cargo.toml` or `go.mod` from `[<language>].src` up to the project root; the root for a Python package with none), with the package's own config. Python: `ruff format --check`, `ruff check`, `pyright`. TypeScript: `tsc --noEmit`, and `eslint` when the package configures it (otherwise the report prints `eslint skipped`). Rust: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`. Go: `gofmt -l`, `go vet`, and `staticcheck` via `go run honnef.co/go/tools/cmd/staticcheck@v0.8.1`. A tool that cannot be found fails its language with exit code 127 and is named. The exit code is the worst tool's, and the last line names each failing language and the tools that failed it. A Python package with no Ruff config of its own is linted with the config `generate` formats with, plus Ruff's default rules (`truewire/resources/ruff-lint.toml`). The behaviour is `truewire.lint`, importable without the CLI.
- **`truewire score` runs `lint` (S7)** per declared language, where it printed `unchecked`.
- **`truewire conform`**: one live call per recorded HTTP request, through the project's own generated Python client and core, judged three ways: the raw body against the response schema (`drift`), the client's own handling of a body the schema accepts (`client:python`), and the body's shape against the recording (keys, types, nullability, element shape, status; values never). Writes `<state>/<project>/<date>.json` and `.md` and a ledger of first-seen dates. GET only unless `--allow` names a read sent as a POST. See `docs/conform.md` and ADR 0012.
- **A file holding a secret's value fails the build** (`docs/shape/workspace.md`, W14).
  `truewire standards` has a new `secret-values` check, on by default and at `error`
  severity. It reads the value of every `[secrets].required` and `.optional` variable
  from the environment and from `.env`, and searches every file that can enter the tree
  for it: what `git ls-files` lists (tracked, or untracked and not ignored), or the whole
  project outside `.git`, `.venv`, `node_modules`, `target` and `.truewire` when it is not
  a git repository. Recordings, `endpoint.json` notes and `dev/capture/` scripts are all
  covered, and so are file names. A value is found as written, percent-encoded (either
  hex case, `/` kept or not, `+` for a space), JSON-escaped (`\/` too), or inside a base64
  blob (an echoed `Basic` credential). A finding names the variable, the file and the JSON path,
  never the value. `truewire capture` runs the same search over the pair it is about to
  write and writes nothing on a hit; `--scrub` the field it names. The wire request is not
  searched, because an authenticated call always carries its key in a header, and headers
  are never recorded. Values shorter than 8 characters are skipped with a note. Neither
  command prints a secret's value: `capture` redacts every line it prints (a key in a base
  URL's path, an error body, the output of its `--check` step), and `standards` redacts the output of the checks it re-runs,
  as `<NAME>`.
- **`truewire call python <endpoint> [key=value ...]`** (`docs/shape/toolchain.md`, P11).
  Instantiates the generated Python client with `<Root>.new(...)` and makes one call. The
  variables `[secrets]` names are read from the environment, else from `.env` at the
  project root. Each goes under the string-typed `new` keyword its name ends with
  (`PETSTORE_API_KEY` as `api_key`), or under the one `--secret keyword=NAME` names; the
  value never goes on the command line. It exits 1 before any request when a required
  variable is unset, when a set one matches no keyword, or when two match one keyword.
  `--base-url`, `--ws-url` and `--new key=value` override the rest, so it points at
  `truewire mock`. Arguments are API-named and bound through the method's own types. A
  missing, unknown or ill-typed argument exits 1 naming it, and a Python name (`pet_id`)
  is pointed at its API name (`petId`). An `rpc` reply prints as JSON, dumped through its
  declared type, so a timestamp reads as the wire writes it. A `stream` prints the reply,
  then each message, one line each, until SIGINT, SIGTERM or a closed stdout (`| head`).
  Then it unsubscribes, prints the unsubscribe reply on stderr, and exits 0. It exits 1
  if the server does not answer within 10 s. A signal before the subscribe is answered
  cancels it. A second Ctrl+C exits 130 at once. The behaviour is importable as
  `truewire.call`.
- **`truewire call typescript` and `truewire call rust`**: the same call, through the
  generated client in that language. `init` writes no TypeScript or Rust constructor, so
  `call` builds the client the way both examples' cores do: `new <Root>(new Core(options))`
  with `Core` and `CoreOptions` from `<package>/core/index.ts`, and
  `<Root>::new(core::CoreOptions { .. })` with `CoreOptions: Default`. The secrets,
  `--base-url`, `--ws-url` and `--new` set `CoreOptions` fields, read from the core's
  source and matched in snake_case (`PETSTORE_API_KEY` finds `apiKey`). A core without
  `CoreOptions` exits 1 saying so. Each `key=value` becomes its wire value by the
  endpoint's argument schema (a string stays a string, anything else is read as JSON),
  and the generated codec decodes and validates it, so an ill-typed argument exits 1
  naming it (`ValidationError: expected integer, got "two" at /page`). TypeScript runs
  under Node 22.15 or later from the package's sources (`node_modules` installed). Rust
  builds a small driver under `.truewire/cache/call/rust/` against the crate and its
  `Cargo.lock`, in the crate's `target/`: the first build compiles the dependencies (about
  a minute), and later calls take under two seconds. Replies, messages and errors print
  as `call python` prints them, and Ctrl+C, a second Ctrl+C and `| head` behave the same.
  The driver runs in its own session and exits when the CLI's pipe to it closes, so a
  closed terminal or a killed CLI does not leave it holding a subscription. It starts with
  SIGINT at its default even under a script's `&` job, and Node older than 22.15 is refused
  with a message.
  What differs is what each runtime keeps. TypeScript and Rust keep keys the types do not
  declare, and Python drops them. `@truewire/core` writes every ISO timestamp with
  milliseconds (`...02.000Z`). The driver reads the call, secrets included, as JSON on its
  stdin, never on its command line, where `ps` would show them to every local user.
  An integer past 2^53 keeps its digits through the TypeScript client both ways, as an
  argument and in what it returns.
  `call rust` keeps one driver crate and binary per set of `CoreOptions` fields a call sets
  (`.truewire/cache/call/rust/<digest>/`, `truewire-call-<digest>`), so two calls at once
  never run each other's build and drop a field such as `base_url` or `token`.
- A `ValidationError` from binding a recorded example to a generated method now carries a
  note naming the parameter (`parameter: limit`).
- **`new(proxy=...)` in every `truewire init` core** (`docs/shape/packages.md`, P18). The
  `bearer`, `hmac`, `jsonrpc` and `ws` templates take a proxy URL and hand it to
  `HttpClient(proxy=)`, and `ws` to its socket too, so one keyword routes REST calls and
  subscriptions alike; `None` falls back to `HTTPS_PROXY`. A project already initialised
  keeps its own `core/__init__.py`: add the keyword to `ClientBase.new` by hand. The
  `github` and `kraken` examples take it too. `init` now writes `truewire-core>=0.3.0,<0.4`,
  the first core with `proxy=`, and the toolchain requires it too.
- **`truewire test [language]`** runs each declared package's own suite the way its CI does: `python -m pytest --verbosity=-1` with `[python].src` on `PYTHONPATH`, the lockfile's package manager's `test` script, `cargo test`, `go test -v ./...`. Each harness starts `truewire mock` itself; `TRUEWIRE_BIN` points it at this toolchain. The run prints one line per language and exits 1 naming the ones that failed. A suite that passed no test fails (`ran no tests (N skipped)`): none found, every one skipped, or no summary to count. So does one that cannot run: no manifest, no `node_modules`, the tool not on `PATH`, pytest not installed. `truewire score` measures S6 `tests` with it, per language, where it printed `unchecked` before.

- **Skills vendored from the package: `truewire agents update` and `truewire agents check`**
  (`docs/shape/agents.md`, A10, A11). The six skills and their README are package data
  (`truewire/resources/agents/`), so a wheel install has them. `truewire init` writes them
  into `.agents/skills/<name>/SKILL.md`, each with a line naming the toolchain version that
  wrote it and a digest of the text, and `.agents/rules/<language>.md` for each declared language the package has
  rules for. `agents update` rewrites the copies from the installed toolchain
  and removes stamped ones it no longer ships, if unchanged; `agents check` exits 1 naming
  each copy that is missing, edited or stale, unless it carries the line
  `<!-- truewire: local edit -->`. `truewire standards` runs `agents check`, so a project
  without vendored skills fails S8 until `truewire agents update` (or `truewire init` over
  it) writes them. `init` no longer keeps `.agents/skills/` with a `.gitkeep`.

- **`truewire init` cores send what the recording has.** The `bearer`, `hmac` and `ws` templates dump a request through its generated type in JSON mode before it goes on the query or path, so `since=2026-01-01T00:00:00Z` rather than `str(datetime)`'s `2026-01-01 00:00:00+00:00`, and `bearer` and `ws` send a JSON body with `Content-Type: application/json`. The petstore quickstart's `list_pets(since=...)` and `create_pet` got 422 from `truewire mock` without either. A project already initialised keeps its own `core/__init__.py`: copy the two changes into `Endpoint.request` and `Transport.send` by hand.
- **`truewire init` writes the workspace skeleton** (`docs/shape/workspace.md`): besides
  `truewire.toml` and the Python core, `.gitignore`, `packages/`, `docs/` (`docs.yml`,
  `index.md`, `api-keys.md`, `how-to/`, `reference/`), `.agents/skills/`, `.agents/rules/`,
  `AGENTS.md`, `CLAUDE.md`, `dev/capture/` and `.truewire/codegen/`. It is idempotent: an
  existing file is never overwritten, a second run prints `Nothing changed`, and a run over
  an existing project fills in only the skeleton it lacks, leaving `truewire.toml` and the
  package as they are. A project that `init` previously refused as already existing is now
  filled in. Run inside the project, `truewire init <name>` is that re-run when the
  directory or `truewire.toml`'s `[project].name` is `<name>`; it no longer nests a second
  project in `<name>/<name>/`. Over an existing project the skeleton is titled after
  `truewire.toml` (`[python].name`, else `[project].name`), not the directory, and `init .`
  no longer needs the directory's name to be a package name. `init` creates each file
  exclusively, so it never writes through a symlink standing where a file would go.
- **The docs pages `init` writes are stubs, and `truewire score` says so**: each carries
  `<!-- truewire init: a stub; replace this page -->`, and S9 counts a page that still
  carries it as missing.
- **`.gitignore` from `init` no longer ignores all of `.truewire/`**, only
  `.truewire/cache/`, alongside `.env`, `.venv/` and `__pycache__/`. The codegen manifest is
  meant to be committed. An existing `.gitignore` keeps its lines and their line endings,
  but for a bare `.truewire/` (or `.truewire`) an older `init` wrote: `init` rewrites it in
  place to `.truewire/cache/` and says so, or drops it when a cache line (`.truewire/cache`,
  with or without a leading or trailing `/`) is already there. A `.gitignore` that is a
  symlink is left alone; a broad rule behind that link prints a reminder to narrow it
  by hand. A UTF-8 BOM is preserved and does not hide the first rule from narrowing.
  Existing bytes are preserved using UTF-8 with surrogate escape, and appended lines
  follow the last existing line ending, including in files with mixed endings.
- **The codegen manifest is `.truewire/codegen/<language>.json`** (was
  `.truewire/<language>-files.json`), and is committed. Same format and version.
  `generate` moves a manifest it finds at the old path and prints one line saying so,
  which adds that git still ignores the moved manifest when an older `.truewire/` line does
  (`truewire init .` narrows that line). The rule source is shown relative to the workspace
  (absolute paths stay absolute); only a broad rule in its own `.gitignore` suggests
  `truewire init .`, and other rules name the file and line to change; `generate --check` reads either, but fails on an old one as a stale manifest until
  `generate` has moved it; `generate --delete` reads either and removes both.
- **`[secrets]` is validated**: `required` and `optional` are lists of environment variable
  names, and any other key, a value, a path, a repeated name, or a name in both lists is
  an error.
- **`[policy]` is a `truewire.toml` section**: `rate` (a finite positive number of requests per second), `retry`
  (default `false`) and `refuse` (endpoint ids). `truewire check` fails on a `refuse` id
  that names no endpoint. No backend renders `rate` or `retry` yet.

## 0.10.1 (2026-09-11)

- `truewire --version` (and `-V`) prints the installed toolchain version. It was the first command a newcomer ran after `pip install truewire`, and it was an error.

## 0.10.0 (2026-09-09)

**Breaking, Rust backend only.** The generated root struct's constructor is renamed and
takes its core by value. Regenerate, and change the one line that builds the client.

- **The generated root is constructed with `from_core`, not `new`.** The root is the one
  struct a caller ever constructs, and it had the good name, so a hand-written core had
  nowhere to put a better one -- two inherent `new`s on one type collide. `new` is now
  left free, and a core defines it as an inherent impl on the generated type, in the same
  crate: the Rust answer to the base class `[python.cores.root]` names in the Python
  backend. A composite root is `from_cores`, one parameter per declared field, as before.
- **It takes `impl HttpEndpoint<Meta> + 'static` rather than `Arc<dyn ...>`.** The `Arc`
  is the generator's storage decision, not the caller's, so the root wraps what it is
  given. `truewire-core` 0.1.1 implements the endpoint traits for `Arc<T>`, so a core
  already shared between clients still fits the same parameter.

Together those turn the first line of every Rust client from

```rust
let client = GitHub::new(Arc::new(Core::new(CoreOptions::default())));
```

into

```rust
let client = GitHub::new(CoreOptions::default());
```

with the core supplying that `new`. `examples/github` shows the impl; `docs/rust.md` says
why it is shaped this way.

## 0.9.1 (2026-09-09)

Both findings come from building the weather.gov showcase, which is the point of building
one.

- **An enum member spelled like its own record broke the generated Python.** A record's own
  name is quoted inside its class body, because generated code cannot use `from __future__
  import annotations` and a recursive field would otherwise raise `NameError` at import.
  That substitution was textual and unconditional, so it rewrote string literals too: a
  record `Alert` whose own `messageType` is `Literal['Alert', 'Update', 'Cancel']` came out
  as `Literal[''Alert'', ...]` -- a syntax error in `schemas.py`, so nothing downstream ran
  at all. `api.weather.gov` really is shaped that way. The substitution now skips the string
  literals already in a rendered type expression, which also makes it idempotent, which it
  was not.
- **Rule 18 now refuses a router group that collides with a shared schema.** A `forecast/`
  group beside a `Forecast` in `schemas.json` renders one name for two things, because the
  module composing the group also imports the shared types. `truewire check` passed it,
  Python generated and ran, and `tsc` then refused it (`TS2440`/`TS2395`) -- one backend's
  silence is not evidence a name is free. It is refused at the gate now, in either
  direction, with both renames named in the message.

## 0.9.0 (2026-09-09)

- **The Rust backend renders a composite root, and stream endpoints.** A router whose core
  hands different children different transports had no Rust rendering, and skipping the
  root took every descendant with it: a client that speaks both HTTP and a WebSocket -- the
  combination Truewire exists for -- produced its types and nothing else. A composite `new`
  now takes one parameter per declared field (`Bluesky::new(client, socket)`), handing each
  child the field `[cores.<name>] children` maps it to; a child that is itself composite
  takes its own fields, so they pass straight through. `kind: "stream"` endpoints render as
  `subscribe`, typed and `_raw`, over the runtime's `StreamEndpoint`. The Bluesky showcase
  went from 3 generated files to 22, compiles with warnings as errors, and replays its
  recordings over a real WebSocket.
- **A skipped Rust router said so; the eleven endpoints it took with it did not.** Modules
  that rendered and were then dropped as unreachable are now reported, with their names, so
  the size of a hole is visible rather than inferred from a file count.
- **`_size` was bound for every Rust walk and read only by two of them.** Every
  cursor-paged endpoint carried two dead lines and a `unused variable: size` warning -- six
  on a clean build of one client. It is bound where it is read.
- **`truewire mock` can serve a browser.** It sent no `Access-Control-Allow-Origin` and
  answered `OPTIONS` with 501, so a generated client running in a browser could not be
  tested against it at all: the preflight failed before the request was made. It now sends
  the headers and answers the preflight.
- The core-shape computation that decides what a router's constructor takes moved to
  `truewire.codegen.shapes`, shared by the TypeScript and Rust backends rather than
  duplicated. A subtree a backend rendered nothing for no longer contributes a field, which
  used to render as `Arc<dyn >`.

## 0.8.2 (2026-09-08)

- **`truewire capture` recorded the wrong exchange, and it could be a credential.** It
  wrote `exchanges[-1]`, the *last* request that went through `truewire_core.http.HttpClient`
  during the call, rather than the one belonging to the endpoint being captured. A
  hand-written core legitimately sends more than one request around an endpoint call --
  minting an OAuth token, refreshing an expired one, fetching a WebSocket ticket, retrying
  after a 401 -- and whenever one of those landed last, *its* response body was written to
  `spec/endpoints/**/examples/<id>.response.json`, then committed and published. A token
  endpoint's 200 body is an access token, so a capture through such a core could publish a
  live credential to a public repository, which is exactly what `docs/spec/authoring.md`
  rule 6 exists to prevent. `truewire check` catches it only when the foreign body happens
  to violate the endpoint's response schema, and the file is written before the check runs
  either way, so the recording is on disk regardless. **Anyone who captured through a core
  that makes more than one request should re-read every recorded response it wrote, and
  rotate any credential that appears in one** -- a value published in a git history stays
  published after the file is deleted.
  `capture` now records the exchange the endpoint declares: its method plus its `path`
  filled from the call's own parameters, matched against the tail of the wire URL path
  (so a base URL's own prefix and any query string are ignored), or, for a JSON-RPC-shaped
  endpoint whose `path` is a method name, that name read off the posted frame at the
  envelope's selector. No match records nothing and fails, naming the endpoint, the route
  it expected and every request the core actually made -- method and path only, since a
  header, a request body and a response body are where a credential would be, and an
  `ApiError` message is withheld for the same reason. Several matches are all this
  endpoint's own attempts (a retry re-sending the same call), so the last stands and the
  output says how many matched. Every capture now reports which exchange it recorded and
  which it skipped; there is no flag that restores the old behaviour.
- `truewire_core.http.recording()` (and its TypeScript and Rust twins) document that the
  list holds everything the core sent and that an exchange is identified by its request,
  never by its position -- the assumption that produced the bug above was taught in their
  own examples.
- `truewire.spec.rpc_selector`: the rule naming an RPC frame's operation (`envelope.selector`,
  or JSON-RPC's `method`), moved out of `truewire.mock` so the mock server and `capture`
  read one canonical definition.

## 0.8.1 (2026-09-08)

- **A router group may no longer claim a class name that is already taken**
  (`docs/spec/authoring.md` rule 18). A client whose declared `name` matches one of its
  router groups generated code that did not build: Rust's `client.rs` imported
  `crate::weather::Weather` and then declared its own `Weather`, so the root struct
  contained itself (`E0255`, `E0072`, `E0391`), and TypeScript's `main.ts` did the same
  by bare import (`TS2440`, `TS2395`). Python raised nothing at all -- the class shadowed
  the import, so `client.weather` returned another root client and every endpoint under
  the group became unreachable. The same shape one level down (a group whose class name
  is its parent group's) and sideways (`list-orders` and `list_orders`, which both render
  `ListOrders`) is refused with it. `truewire check` reports it as an `error` naming the
  client, the group and the `router.json` it comes from, and `truewire generate python`,
  `typescript` and `rust` refuse the same condition before writing a file. The rename is
  never made for you: the root class name and every group attribute are the client's
  public surface.

## 0.7.0 (2026-09-08)

- The toolchain and `truewire init` now require `truewire-core>=0.2.1`, the release whose
  converters accept an already-parsed `date`/`datetime`; a generated request carrying a
  real `date` fails to validate against 0.2.0.
- **`truewire generate typescript` renders stream endpoints.** A `kind: stream` endpoint
  is a class over `StreamEndpoint<Meta>` whose method returns the core's
  `Subscription<Message>` (`Subscription<unknown>` under `validate: false`), handing the
  core what the Python backend hands `self.subscribe(...)`: the channel template with the
  `Parameters` object and its codec, or the channel filled from the parameters for a
  direct-channel or connect-only stream. `@truewire/core` exports `Subscription` from its
  root for it.
- **`truewire generate typescript` composes cores.** A router under a core declaring
  `children` or `forward` takes a fields object, exported as the `<Class>Core` interface,
  and hands each child its declared field, or the whole object to a composite child;
  `params` needs no rendering, since generated code never builds a core (ADR 0011). The
  groups this used to skip (`examples/kraken`'s `root` and `streams`) are generated. The
  one remaining skip is the `ws` half of an `rpc` endpoint declaring both transports.
- **`examples/kraken` generates TypeScript** beside its Python package: a hand-written
  core in three transports (REST with HMAC-SHA512 signing and a nonce, two WebSocket v2
  connections over `ws.StreamsRpc`), and a vitest suite against `truewire mock` mirroring
  the Python one. CI's `examples-ts` job runs both examples through `generate typescript
  --check`, `tsc` and `vitest`.
- **Recursive schemas render instead of crashing.** A schema may reference itself --
  directly, through an array's `items`, or around a cycle of several schemas -- as long
  as one schema on the cycle is a record (`docs/spec/authoring.md` rule 17). Two records
  referencing each other used to pass `truewire check` and then raise
  `CircularDependencyError` from `generation_order`; the order now collapses each cycle
  before sorting, and the reference that points forward is emitted quoted. A cycle where
  *no* schema is a record cannot be expressed at all: it used to pass `truewire check`
  and then either die in generation with a bare `RecursionError` or emit an alias naming
  itself (`Node = dict[str, Node]`, a `NameError` on import). It is now one
  `schema-cycle` violation naming the schemas on it, and generation refuses the same
  shape with a `SchemaCycleError` if the gate is skipped. `LocalResolver`'s unreachable
  `Cycle detected` guard is gone -- its mapping never held a reference for it to loop on.
- **`truewire capture` drops the stale `unverified` block.** The pair it writes is the
  evidence the declaration said was missing (ADR 0001), and leaving the block in place
  failed `truewire examples` on the next run. `capture` now removes it from
  `endpoint.json`, every other key kept in place, and says so. The `examples` failure for
  a stale declaration names the endpoints in the message itself instead of asking for
  `--verbose`.
- **`truewire generate python --check` compares content.** It reported only manifest
  ownership and file existence, so an owned file whose body was stale passed; it now
  renders the plan the way `generate` writes it (banner, Ruff formatting) and lists every
  owned file that differs as `out of date`, exiting non-zero, the way the TypeScript path
  already did.
- **`truewire init .`** writes the project into the current directory and names the package
  after it (`open-meteo` -> `open_meteo`); so does `truewire init <name>` run inside an
  empty directory named `<name>` (a `.git` or `.venv` there does not count). Anywhere else
  `truewire init <name>` still creates `./<name>`. An existing `.gitignore` gains the
  lines `init` writes instead of being replaced.
- **`generate --check` works without a manifest.** `.truewire/` is gitignored, so on a
  fresh clone `--check` failed with `missing manifest` and CI could never run it. Both
  backends now take the plan as the owned file list when `.truewire/<language>-files.json`
  is absent -- the plan names every file `generate` would write -- and check existence
  and content the same way, saying that the plan stood in; the one difference only a
  manifest can show (a file an earlier plan owned and this one does not) waits for the
  next `generate`. CI runs `truewire generate python --check` on both examples.

  summary, or as JSON for a second backend, a docs site or a test.

- **The generator reads a declared core contract and never imports the target package**
  (ADR 0011). Composing a child through `.new()` is declared in `truewire.toml`:

## 0.4.0 (2026-09-07)

- **A response schema describes the wire body; `envelope.payload` selects the returned
  value** (ADR 0010, authoring rule 6). Before, the schema described the value the core
  returned after unwrapping and `truewire check` extracted `envelope.payload` from a
  recording before validating. Now the schema describes the whole recorded frame, the
  checker validates the recording against it as-is, and the generator types the method's
  return value from the schema at `envelope.payload`. The method still returns the
  unwrapped value; cores, the mock server, `truewire capture` and `envelope.correlate` are
  unchanged. Pagination paths stay relative to what the method returns. `truewire import
  openapi` keeps writing the document's response schema, which was always the wire body.
  A new `envelope` lint rule (error) requires `envelope.payload` to name a property of the
  response schema. Stream `payload` schemas are unchanged.
- `truewire migrate`: rewrites a spec written under the previous rule. For every rpc
  endpoint declaring `envelope.payload` whose response schema does not carry that path,
  it wraps the schema into the frame its recordings show (`<Title>Frame`, other keys
  inferred and described as wire fields, the old schema under the payload key). It
  refuses an endpoint with no recording; `--template <function>` names a recorded
  endpoint whose frame stands in. A second run changes nothing.
- `examples/kraken` migrated with the command: 64 endpoints, generated source unchanged.
