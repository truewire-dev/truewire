# Go rules

The style the Go module must satisfy: generated packages, the hand-written core, `New`,
hand-written methods and `tests/`. Each rule names the tool that enforces it, or says
"(review)" when a reviewer checks it by reading the code.

## Tools

`truewire lint go` runs three tools in the package, the nearest directory at or above
`[go].src` that holds `go.mod`. All three must pass:

- `gofmt -l .` prints nothing. It covers every `.go` file, tests included.
- `go vet ./...` exits 0. This also compiles the module.
- `go run honnef.co/go/tools/cmd/staticcheck@v0.8.1 ./...` exits 0. No `staticcheck.conf`
  ships, so it runs the default checks. Those leave out ST1003 (naming) and
  ST1000/ST1020-ST1022 (doc comments), which is why the naming and doc rules below are
  review rules. To check them, run staticcheck with
  `-checks ST1003,ST1000,ST1020,ST1021,ST1022`. In files headed
  `// Code generated ... DO NOT EDIT.` ST1003 and ST1020-ST1022 report nothing even when
  enabled; ST1000 and the default checks (ST1005 error strings, for one) still apply.

## Generated and hand-written

- Generated files start with `// Code generated by truewire. DO NOT EDIT.` Never edit one:
  change the spec or the core and regenerate. `truewire generate go --check` fails on
  drift.
- When a generated file fails a tool, the generator is wrong. Report it; do not patch the
  file. (review)
- Never put the banner on a hand-written file: staticcheck's naming check and its
  exported-identifier doc checks would skip it. (review)
- Hand-written code lives in three places:
  - the core package;
  - `New`, in the root package beside the generated `FromCore`;
  - a `handwritten` surface's method, in a `.go` file in the parent router's package,
    named `PascalCase` of the surface symbol's method. `truewire surface --language go`
    checks these.

## Naming (review)

- Exported names are `PascalCase`, unexported ones `camelCase`. In a hand-written name an
  initialism on staticcheck's ST1003 list keeps one case: `NodeID`, `HTMLURL`, `baseURL`,
  `ChainRPC`, never `NodeId` or `ChainRpc`. Generated names follow the generator's own
  list, which differs (a `db_id` field is `DbID`, not `DBID`): refer to a generated name as
  it is generated. The runtime's `HttpClient`, `HttpEndpoint` and `RpcEndpoint` keep
  their names.
- Package names are lower-case words run together, with no underscores (`listcommits`).
- The runtime is imported as `truewire "truewire.dev/core"`.
- Every hand-written package and exported identifier has a doc comment that starts with
  its name: `// Options is what New takes.`

## Types and errors (review)

- Type-assert `call.Meta`, or an interface on a router's `core` field, with comma-ok. On a
  mismatch, return `truewire.LogicError`. Never panic.
- An HTTP or WebSocket core returns the wire body as `json.RawMessage` with the envelope
  unwrapped and never decodes into response types. A gRPC core implements
  `Endpoint` from `truewire.dev/core/grpc`, whose `Invoke` decodes into `Call.Response`
  (a `proto.Message`). A hand-written call that does not return JSON (the Kraken
  example's `RetrieveExport`) has its own shape.
- In Go, a required integer the caller left unset is 0. Code that clamps or defaults a
  request field leaves a zero as the caller sent it.
- A core builds its errors with the runtime's constructors (`truewire.APIError(kind, msg)`,
  `LogicError`, `ValidationError`, `NetworkError`, `NewError`). It never uses
  `errors.New`, `fmt.Errorf` or an error type of its own, so callers can match with
  `errors.Is(err, truewire.ErrAuth)` and `errors.As(err, &e)`.
- Where the API distinguishes them, map 401/403 to `KindAuth`, 429 and rate-limit 403s to
  `KindRateLimited`, and 400/422 to `KindBadRequest`. Those are defaults: an API-specific
  mapping may go further (the GitHub example maps 404 to `KindBadRequest`), and `KindAPI` is for a
  failure no more specific kind fits. Attach `.WithBody(...)`, plus `.WithStatus(...)`
  for a non-2xx reply.
- A missing credential returns `APIError(truewire.KindAuth, ...)` before anything is sent.
- Never turn an error into a nil error. Return the runtime's errors unchanged.

## Context, transport, dependencies (review)

- A hand-written method takes `ctx context.Context` first and passes that `ctx` to every
  call it makes. A core never calls `context.Background()` or `context.TODO()`.
- An HTTP core passes `call.Options.Timeout` on as `truewire.RequestOptions.Timeout`, so
  that `truewire.WithTimeout` works.
- HTTP goes out through `*truewire.HttpClient` and WebSocket through
  `truewire.dev/core/ws`. Never call an `http.Client` or dial a socket yourself:
  exchange recording and error kinds live in the runtime.
- Credentials come from the core's `Options`. A core never reads `os.Getenv`.
- Require `truewire.dev/core/grpc` or `truewire.dev/core/protoframes` only for gRPC
  endpoints or protobuf frames. `truewire.dev/core` itself needs only `coder/websocket`.

## Tests

- `tests/` replays the recordings against a local mock: `twtest.ReplayHTTP` with
  `twtest.StartMock`, and `grpctest.Replay` with `grpctest.StartMock` for gRPC. Tests
  never call the live API. (review)
- `truewire test` runs `go test -v ./...`. A suite where no leaf test passes fails, even
  when every test was skipped.
