# Python rules

The style the project's Python package must satisfy: the generated client under `src/<pkg>/`
and the code written by hand beside it (`src/<pkg>/core/`, the files `[[python.extras]]`
names, `test/`). Each rule says what enforces it: a tool, or `(review)` for a reviewer.

## Tools

`truewire lint python` runs these in the package directory (the nearest one from
`[python].src` up to the project root that holds a `pyproject.toml`, else the root), over
everything in it: `test/` too, and Markdown code blocks from Ruff 0.16 on.

```
ruff format --check --no-cache [--config <file>] .
ruff check --no-cache [--config <file>] .
pyright
```

- Ruff's config, first match wins: `[python].ruff`; the package's own `ruff.toml`,
  `.ruff.toml` or `[tool.ruff]`; else the toolchain's `ruff-lint.toml`. That one extends
  `truewire/resources/ruff.toml`: 2-space indent, single quotes, target Python 3.11, Ruff's
  default line length, lint rules `TID251`, `E4`, `E7`, `E9` and `F`.
- Do not add a package `ruff.toml`, `.ruff.toml` or `[tool.ruff]`: `generate` never reads
  it, so generated files fail its format and rules (`UP035` even asks for the `typing`
  imports TID251 bans). Change Ruff settings only through `[python].ruff`, which `generate`
  and `lint` both use. (review)
- `truewire lint python` exits 0, hand-written files included. Fix them with the same
  `--config` the lint runs. (`truewire lint python`)
- pyright reads `pyrightconfig.json` or `[tool.pyright]` there. The core skill writes
  `"include": ["src", "test"]`, `"typeCheckingMode": "standard"`.

## Generated and hand-written

- A file that starts `# Generated by truewire — do not edit by hand.` is never edited.
  Change the spec or the core and regenerate. (`truewire generate python --check`)
- A generated file that fails ruff or pyright is a toolchain bug. Report it; do not
  patch the file. (review)

## Imports and typing

- Typing names come from `typing_extensions`, never `typing`. (ruff TID251)
- No `from __future__ import annotations`: it breaks pydantic's runtime validation. Quote
  a forward reference instead. (ruff TID251)
- pyright reports 0 errors over `src` and `test`. (pyright)
- A core base satisfies its `truewire_core.contract` protocol (`HttpEndpoint`,
  `ClientRoot`, ...); a mismatch is a pyright error in the generated code calling it. (pyright)
- A module that re-exports names lists them in `__all__`. (ruff F401)
- A name is imported from the module that exports it, not one that only imports it; an
  installed package gets `reportPrivateImportUsage` for the second. (review)
- A core `__init__.py` using `lazy_loader.attach_stub` has an `__init__.pyi` that imports
  every exported name and lists it in `__all__`. (review)
- Every `datetime` hand-written code creates or compares is aware: `datetime.now(timezone.utc)`,
  never `datetime.now()` or `utcnow()`. The runtime reads a naive one as local time in epoch
  formats and as UTC in ISO. (review)

## Naming and docstrings

- Classes are PascalCase; functions, methods, parameters and attributes snake_case;
  constants UPPER_SNAKE (`RATE`, `AUTH_CODES`). A parameter named after a Python keyword
  gets a trailing underscore (`from_`), as in generated methods. (review)
- Docstrings use Google sections (`Args:`, `Returns:`, `Raises:`, `Examples:`, `References:`);
  a multi-line one closes `"""` on its own line. (review; `truewire standards --only
  docstrings -v` lists violations under `src/` as warnings and still exits 0)
- No `__call__` method under `src/<pkg>/`, hand-written included: give it a name.
  (`truewire standards --only no-call`)
- A hand-written `<name>_paged` walker returns `truewire_core.PaginatedResponse[...]`,
  never an async generator. Spell the annotation so it ends in the name
  `PaginatedResponse` (quoted or dotted is fine); an `import ... as` alias or a type alias
  of it fails the check. (`truewire standards --only paged-shape` when a `def <name>` is in
  the class or in a base under `src/<pkg>/` that its module defines or imports at top level;
  review otherwise)

## The core

- Every class a `[python.cores.*]` `base` names is a `@dataclass(kw_only=True)`; endpoint
  bases are also `frozen=True`. (review)
- The root's `new` is a `@classmethod` with keyword-only parameters returning `Self`. It
  keeps `validate=` and `proxy=` and builds `HttpClient(proxy=proxy, rate=cls.RATE,
  retry=cls.RETRY)`. (review)
- Traffic goes through `truewire_core` (`HttpClient`, `Socket`, `Streams`, `Rpc`,
  `StreamsRpc`): no `httpx.AsyncClient`, no `websockets.connect`, no class named like a
  runtime primitive that does not inherit from it. (review)
- Signing happens inside an `httpx.Auth` passed to `HttpClient.request(auth=...)`, so each
  attempt is signed after pacing and retry waits; never before the call. (review)
- The core never reads `os.environ`: the caller passes credentials to `new`.
  (review; `grep -rn os.environ src/<pkg>/core` finds nothing)
- A dataclass field holding a credential is `field(repr=False)`, so `repr(client)` shows no
  secret. (review)

## Errors

- The core raises only `truewire_core.exceptions` classes, never one of its own. An error
  the API returned is `ApiError`, or where the API distinguishes them `AuthError`
  (401/403), `RateLimited` (429, rate-limit 403s) or `BadRequest` (400/422 and other 4xx
  the caller caused). A transport failure is `NetworkError`, a reply that fails its schema
  `ValidationError`, as the runtime raises them; a misused client is `LogicError`. (review)
- The message carries the API's own error text and its status or code; an error never
  becomes `None`, a default, or an empty result. (review)
- A missing credential raises `AuthError` before any request, never `KeyError`. (review)
- An httpx, websockets or pydantic exception reaches the caller as a `truewire_core`
  exception raised `from` it. (review)
- A handler catching `BaseException` or `CancelledError` cleans up and re-raises. (review)

## Dependencies and tests

- Every third-party module `src/` imports is in `[project].dependencies`, not only in a
  dev extra. (review)
- The `truewire-core` floor is the first release shipping every `truewire_core` name the
  package imports, generated code included; keep the cap `init` writes. (review)
- Tests reach the API through `truewire mock` by overriding `base_url`, or through a local
  server for behaviour the mock cannot produce (a 429 with `Retry-After`); never the live
  API. `test/` holds a typing-usage file pyright checks. A walk test drives the real walker
  across recorded pages, not a state built by hand. (review)
